# Inbox

Low-friction capture for ideas, cross-project findings, raw artifacts, and "do not lose this" notes that surface while working elsewhere.

## Capture Rules

- Prefer one self-contained Markdown file per finding.
- Preferred naming: `YYYY-MM-DD-<source-project>-<short-slug>.md`.
- Legacy, experimental, or human-created names are still valid inbox items. Do not rename just for neatness.
- Directories are allowed when the capture is a bundle: transcripts, exports, raw notes, generated artifacts, or a larger idea captured before it has been shaped.
- During unrelated work, only add new files or directories here. Do not edit or delete existing inbox items just because you noticed them.

Each Markdown capture should answer, when practical:

- what was observed;
- why it matters;
- which project or area it affects;
- suggested action, if any.

## Lifecycle

Inbox items are raw evidence by default. At the start of substantive work:

1. Review unprocessed items.
2. Treat each as enhancement evidence unless explicitly changing the plan.
3. Promote only low-structural-impact facts into durable docs.
4. Delete or move source items only once their useful content is fully captured elsewhere.

The inbox is intentionally tolerant. Structure belongs after triage, not before capture.
